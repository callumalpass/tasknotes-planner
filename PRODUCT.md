# Product

## Register

product

## Users and purpose

TaskNotes users planning task dates and dependencies on a timeline. The task
ledger and timeline represent the same records, not a separate planning database.

## Brand

Use the existing TaskNotes family language: quiet paper, legible type, precise
rules, restrained blue. Preserve the visual system in [DESIGN.md](DESIGN.md).

## Anti-references

Do not introduce a dashboard sidebar or decorative status cards. Do not expose
internal identifiers or protocol terminology in ordinary sign-in messages.

## Principles

- Preserve one authoritative ledger/timeline scroll and task-row geometry.
- Keep task edits and collection readiness honest; transport is not saved proof.
- Sign-in follows the shared SDK lifecycle, with clear plain-language status.
- Preserve the working runtime until native composition is qualified.

## Accessibility

Keep complete control names, keyboard operation, visible focus, light/dark
appearance and reduced motion. Status must be written, not colour-only.

## Sources

Existing README.md and DESIGN.md; the coordinator's decided sign-in copy.
This records existing product context, not a new visual direction.
